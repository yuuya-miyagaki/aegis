- [confidence:8] `CLAUDE.md` は薄く保ち、詳細ルールは pull-based にした方が Claude Code では安定しやすい。
- [confidence:9] シェルコマンドの control-plane 判定を「正規表現＋クォート span マスク」でやると、シェルの**クォート除去＋隣接トークン連結**（`hooks""/lib`→語 `hooks/lib`）を再現できず分割トークン書込みを取りこぼす。正しくは**語単位にトークン化→各語の literal value を再構成→書込み先語のみ判定**。詳細・OPEN 課題は `docs/security-followups.md` SF-001。
- [confidence:9] 書込み先が安全かの判定は「**安全コマンドのアロウリスト**（echo/printf/git commit 等）」で行う。「write ユーティリティのブロックリスト」は列挙漏れ（perl -i/patch/awk/sponge…）で必ず漏れる。改行は区切りとして扱う（`\n`→`;` 正規化）＝line-oriented grep の取りこぼし防止。
- [confidence:8] STATUS の制御フィールド（gate に続き iter43 で task_type/task_size）を tamper-evidence 化する型は固定: (1) `.gate-snapshot` に取り込む (2) Bash 経由の authorized writer（update-gate.sh / update-task.sh＝PostToolUse を自然バイパス）を用意 (3) post-status-audit に「snapshot≠STATUS かつ snapshot 非空で block」ループを gate と**完全同型**で足す（`[ -n "$OLD" ]` は移行猶予）。同型にすると読み手の心智モデルが1つで済む。tamper-evidence であって proof ではない（block はディスク編集を巻き戻さない・cross-session re-bless は受容）。
- [confidence:8] 副作用を伴う再適用（`aegis_cp_apply` の moat 施錠）は tamper チェックの**後**に置く。冒頭に置くと改竄編集（`task_type:locked→framework`）が検知前に解錠を発火させ、block が無意味になる。ただし no-baseline 経路（snapshot 不在の first-edit）は tamper 不能なので副作用も安全＝「clean 経路＋first-edit でのみ発火する helper」に切り出すと両立する（iter43 で `_aegis_relock_from_status` に抽出）。
- [confidence:7] authorized writer（update-task.sh）は frontmatter 行の **replace だけでなく insert（行欠落時）** も実装する。STATUS テンプレは task_size 行を持たない（任意フィールド）ため、replace-only だと新規プロジェクト初回の size 設定が silent no-op になる（grill-code Critical で発見）。schema 必須フィールド（task_type）欠落時は黙らず明示エラー。
- [confidence:8] check-gate の plan-gate / Client-mode deny は「project の code を編集させない」ゲート。ROOT 外の絶対パス（global auto-memory `~/.claude/.../memory/`）は project code でないので両ゲットの対象外にする＝control-file/templates/docs 判定の**後**・mode/plan 判定の**前**に「`$ROOT/*`・`$ROOT_REAL/*` 以外の絶対パス→emit_allow」short-circuit を置く。`/` anchor が sibling（`/p/aegis-backup` vs ROOT `/p/aegis`）誤判定を防ぐ。相対は防御的に gate 維持（Edit/Write は常に絶対）。empty-`$ROOT_REAL` は `/*` に縮退し keep-gating 側＝fail-safe。`is_control_file` は短絡より前に走り、外部絶対は control パターンに構造的に非マッチなので穴は開かない（iter44 C5）。
- [confidence:7] クォート heredoc（`<<'PY'`）の body 内で `$VAR` を参照すると非展開で dead first path になる（python が常に FileNotFoundError→フォールバック頼み）。値は **argv 経由**で渡す（`python3 - "$VAR" <<'PY'` → `sys.argv[1]`）と、body 非展開のまま（injection 安全＝値は data として渡りコードとして評価されない）実値が届く。grep フォールバックは defense-in-depth として残すが、主経路が実際に機能することを実証するテストを別途置く（iter45 C3）。
- [confidence:7] 2 経路の分岐で「正しい方が勝つ」ことを示す positive-control は、green 状態では負け経路が実行されないため fixture がドリフトすると静かに牙を失う（false-green）。RED-first だけでなく**負け経路を単独実行して誤値を返すことを直接 assert** すると、discriminator が live であることを steady-state CI でも証明できる（盲検 reviewer-testing F1 指摘で追加）。さらに RED の理由を「値の相違」に固定するため、両経路とも rc 0 を保つ仕掛け（grep を空振り=rc1 でなく greedy で誤値に倒す）にして abort と value-miss を分離する（iter45 C3）。
- [confidence:8] bash `gate_value`（permissive）と python `extract_approval_map`（strict allowlist）の parse 乖離は **security ホールではない（実証済み）**。bypass には「bash=approved/n-a ∧ python≠approved」な到達可能行が要るが、(1) 唯一の in-session writer は update-gate.sh＝clean enum、(2) raw Edit は post-status-audit が**任意の**値変化を tamper block、(3) 両消費側は clean トークンでのみ all(check-gate.sh:174 は exact-match／check_status.py は `.get(key,"pending")`)、(4) malformed は PyYAML cross-check(check_status.py:865) でも検出。12 種の weird 形を probe して bypass-direction が **0 行**（残る乖離は全て「片方が stricter＝fail-safe」方向）。さらに重要: `gate_value` を strict 化すると post-status-audit:129-130 の OLD/NEW 比較が `approved`↔`approved `(末尾空白) を同一視して **tamper を取りこぼす**＝backstop 弱体化の net-negative。結論: **permissive のまま据え置く・strict 化しない**。乖離を見たら「security」ではなく「同一概念の二言語実装＝maintainability」と切り分ける（full-review C4・iter46 で grill-premise＋実測で premise を棄却）。

- [confidence:8] 配布 self-containment の参照整合性 guard を **doc 面（CLAUDE.md / .claude/rules/*.md）**へ拡張するときは、検査入力に **install 実体**を読む（iter49 conf8 の doc 面適用）。CLAUDE.md は `setup.sh:resolve_source` で `templates/CLAUDE.template.md` へ remap される＝dogfood の repo-root CLAUDE.md を読むと install されない参照（update-gate/update-task/platform_manifest）を誤検出する（install 実体は `check_framework_contract.py` のみ参照＝maintainer 専用の意図的非同梱で allow-list 化）。rules は remap なし＝verbatim。resolver は**明示 map**（`_DOC_TEMPLATE_REMAP`）で持つ（setup.sh parse 失敗時に空 map→false-clean になる fail-open を避ける fail-closed）。setup.sh:resolve_source の case を parse して resolver との一致を assert する**アンカーテスト**で drift を明示 fail させ、parse は `)`〜`echo` 間の**行コメントを事前除去**してコメント内 `"` の取りこぼし（fail-open）を封じる（iter50・盲検 reviewer-testing F1）。同一 script が `.py 層`と `doc 層`の2 allow-list に出るときは reason に referrer 差（status_doctor.py vs CLAUDE.md prose）を明記する。
- [confidence:8] `permissions.allow` の auto-allow 安全分類は **intent ベース**（mechanism 不可）。`check_status`/`check_framework_contract`/`retro_report`/`build-judge-card` は **fixed-internal subprocess** を持つが安全＝「subprocess を使う」では分類できない。逆に `context_budget.py` は default `check` が読取でも `--tighten`/`--seed` で追跡 config `scripts/context-budgets.json` を書込む＝`Bash(...:*)` matcher は**全フラグを許可**するため must_prompt。mode 依存 write は **default パスでなく全コードパスの write/exec sink を読んで**判定する。さらに「subprocess 一般を禁止」の静的 guard は fixed-internal reader を誤検出＝**偽陽性で不可**（固定 vs arg 制御は静的 undecidable）＝exec-gadget guard は既知 `._execute(` の固定であって網羅ガードではない（iter52・grill-code 🔴 で context_budget を捕捉＋盲検 security が実証）。
- [confidence:7] hook 確認文（permission prompt）の言語一貫性: `emit_ask`→`permissionDecision:"ask"`+`permissionDecisionReason` はユーザーの確認 UI に surface される（emit.sh:52・schema verified）。reason 注入機構と平易日本語の中身は control-plane/secrets/skill-gate/cron-gate/tdd/deploy-gate で**既存**＝「確認文を平易日本語化」は大半が済み。唯一英語だったのは破壊的 WARN 配列（patterns.sh の `AEGIS_DESTRUCTIVE_{LOWER,CMD}_WARN` 18件）＋抽出失敗フォールバック2件＝最高リスク面の言語不整合（iter53）。i18n のドリフトガードは「各 WARN に日本語文字（かな/カナ/CJK）≥1」で ASCII コマンドトークン（rm -r 等）を誤検知せず完全英語回帰を捕捉。だが**真の fail-open は「日本語欠落」でなく「gated REGEX に対応 WARN 欠落」→空の `[careful] ` 発火**＝`*_REGEX`↔`*_WARN` の件数パリティ assert を必須に（盲検 reviewer-testing と security が独立にハードコード件数の冗長を指摘＝parity が真の不変条件）。文字列のみ変更の moat 不変は WARN が assign→emit 専用（分岐述語に非使用）＋REGEX byte-diff＋既存 destructive/secrets テスト green（ask/allow 決定のみ assert で reason 本文未 pin＝テスト更新不要）で実証。
- [confidence:9] **macOS/Windows 既定のケース非依存 FS で deny hook の文字列判定は素通りする＝moat の新規バイパスクラス**（iter54・自己再現）: 小文字リテラル前提の一致（`cp evil HOOKS/lib/emit.sh`・`Edit(CLAUDE.MD)`・`git add key.PEM`）は実ファイルに着弾するのに control-plane/gate/secrets が allow していた。修正型は**条件付き case-fold**: (1) FS ケース非依存性を `[ -d "$ROOT/HOOKS" ] && [ "$ROOT/HOOKS" -ef "$ROOT/hooks" ]` で1回プローブ（`-d` 単独は case-sensitive Linux の実在別 dir HOOKS/ を誤検知＝`-ef` 同一 inode 確認が必須）(2) 検出時のみ fold＝**deny を広げる方向のみ**（allow 側カーブアウト＝allowlist/read-only/bare-git-stage は case-sensitive のまま＝allow は広がらない）(3) credential 名判定は無条件 fold（大文字鍵名は全 FS で実鍵＝純増）。落とし穴3つ: **(a) bash 高速ゲート自体も fold 必須**（`case "$cmd" in *hooks*` 前提の resolver スキップ判定＝bare `rm -rf HOOKS` は regex 層に非マッチで resolver 専任なのにゲートで落ちる）**(b) 陽性 grep を fold したら対の safe-variant strip/除外も対称に fold**（`.ENV.EXAMPLE` の false-deny 防止）**(c) post-status-audit の `*STATUS.md` filter も同クラス**（`Edit(docs/STATUS.MD)` の gate tamper が監査ごとスキップ＝check-gate の docs/* allowlist が Edit を通すため実害）。fold は case-insensitive 時のみ分岐（無条件 `|*status.md` 追加は case-sensitive Linux で `build-status.md` を over-audit）。python 子には `AEGIS_CASE_INSENSITIVE` を**呼び出し時明示代入**（session env 継承なし＝弱体化不能）・テスト強制は strengthen-only `AEGIS_CASE_FOLD_FORCE=1`（OFF スイッチを作らない）。残余＝非ASCII homoglyph（U+212A→k）と大文字コマンド名は**FS 実解決（realpath+inode）リアーキ＝別テーマ**（高速ゲートで非ASCII 全 spawn は日本語ホットパスに過大）。fold プローブの基点は兄弟 hook と同じ SCRIPT_DIR 由来に固定（`CLAUDE_PROJECT_DIR` 依存だと env で fold-off 可＝盲検 security N-1）。
